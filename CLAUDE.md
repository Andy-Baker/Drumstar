# MRM-44 / Drumstar
Browser-Drum-Machine/Sequencer, Vanilla JS + Web Audio: `index.html` (Markup), `css/app.css`, `js/*.js` (klassische Skripte, gemeinsamer globaler Scope), `sw.js` (Service Worker). Gehostet via GitHub Pages. Sprache: Deutsch, knapp.

## Regeln
- Kein Framework, kein Build. Plain HTML/CSS/JS; was im Repo liegt, läuft so. Mehrere Dateien ja, ES-Module/TypeScript vorerst nein (siehe DECISIONS.md).
- Bei jedem Deploy `CACHE` in `sw.js` erhöhen (aktuell `mrm44-v97`) und alle `?v=` an den js/css-Links in `index.html` auf dieselbe Nummer setzen (`tests/test-sw.py` prüft das).
- Skript-Dateien: Reihenfolge = `<script>`-Liste in `index.html`. Code, der beim Laden läuft (oberste Ebene), darf nur Funktionen aus derselben oder früheren Dateien aufrufen bzw. als Wert übergeben — Hoisting gilt nur innerhalb einer Datei. Start-Aufrufe gehören nach `js/main.js` (wird zuletzt geladen). Neue Datei: in `index.html` eintragen, sonst nichts (der Service Worker liest die Liste von dort).
- UI: erst interaktives Mockup (HTML), dann Umbau. Design braucht Platz; dunkles Chassis, blaue Controls, Instrumentfarben (Acid orange, Cosmic lila, Piano gelb, Sample grün, Drums blau, Perc türkis).
- Versionen über Git-Commits/Tags, nicht über Datei-Suffixe.
- Tests gehören ins Repo (`tests/`), nie nur ins Claude-Projekt. Neue oder geänderte Tests immer mit committen und pushen.

## Architektur-Kurzfassung
- Dateien (`js/`, in Ladereihenfolge): `base` (Icons `UI_IC`, `$id`) · `audio` (Engine, Worklet) · `fx` (Effekte, Busse) · `voices` (Metallic, Mic-Sample, Acid) · `events` (Arrangement, Noten-Events, Cosmic- und Piano-Stimme) · `kits` (Drumsets, Sample-Kits) · `tracks` (`TRACKS`, Fill) · `controls` (Knob, Tempo, Übersicht, Spurleiste) · `harmony` · `editor` (Step-Grid, Vorschau, Acid-Auto, XY) · `sheets` (Menüs, Sheets, Klang) · `sample-track` · `wav-export` · `mixer` (Sample-Pads, Mixer) · `sample-editor` · `storage` (Pattern-Speicher, Import/Export) · `beats` (Beats, Kit-Menü, Drumset-Editor) · `pianoroll` · `scheduler` (Scheduler, Standard-Pattern, Default-Beats, Tab-Leiste) · `tempo-detect` (Tempo erkennen) · `main` (Start).
- Melodische Spuren (`type:'arp'`: arp=Acid, cosmic, piano) nutzen `tr.events=[{s,n,l,v,a,sl}]`; `tr.steps` ist abgeleitet (`evTouch`). `isPoly(tr)` = Cosmic/Piano (Akkorde, keine Slides), `trOct(tr)` = Oktavlage.
- Drums/Perc/Sample: `tr.steps`.
- Noteneditor `#prWin` (v64, nach Mockup v3): Kopf `#prTop` (Zurück · Instrument · Klang · Optionen), Werkzeug `#prTool` (Modus · Zoom · Alles zeigen · Undo), Raster `#prView`/`#prCv` über das ganze Pattern mit Zoom/Scroll pro Spur (`tr._prv`), Fuß `#prFoot` = Transport bzw. Notenleiste der Auswahl; Querformat: alles in `#prLand`. Klaviatur mit Übersichtsleiste (`tr._prk`). Buttons per `data-pa`/`data-pm`. Im Hauptfenster zeigen arp-Spuren nur die Vorschau `#prPreview` (`renderEditorArea`). Speicherformat `schemaVersion: 8` (v79: Effekte).
- Klang-Sheet `#klSheet` (`openKlang`): ein Einstieg für alle Spuren; Melodiespuren mit Reitern Sound / Mix & FX / Tonart (Grundton + Skala), Drums/Perc/Sample nur Mix & FX (+ Tune). Mixer-Knopf öffnet dasselbe als „Kanal“.
- UI-Einheitlichkeit (v65): Overlays mit Kopf `.ovt` + ✕-Kasten; Icons als SVG (`UI_IC` in `js/base.js`, CSS `.uic`), keine Emojis in Buttons. Beat-Zeilen über `prowFinish` (▶ + ⋯ mit benannten Aktionen). Mixer: Master in eigener Spalte `#mixerMaster`, Fader-Höhe über `--fh` (`mixerFit`, bis zur Tab-Leiste).
- Harmonie (v62, ersetzt den Arpeggio-Generator): einklappbare Karte `#hmPanel` auf der Pattern-Seite. `harmony={key,chords}` gilt pro Pattern für alle Spuren; `tr.harm` = Spielweise pro Spur (`off|chord|chordbass|root|arp`, Acid ohne Akkord-Modi). Folgt eine Spur, liegen die eigenen Noten in `tr.harmOwn` und `tr.events` enthält die erzeugten (`e.h=1`) — Wiedergabe/Export/Vorschau brauchen keinen Sonderfall. Speichern: `trOwnEvents(tr)` + `harm` + `harmony`. Erzeugte Note in der Piano Roll anfassen = `hmConvert` (Spur bekommt eigene Noten, Undo per Toast). Zufall deterministisch über `tr.harm.seed`.
- FM-Drums: AudioWorklet `fm-voice` (Hüllkurven multiplikativ statt `Math.exp` je Sample; Stimme endet bei −45 dB mit 20 ms Ausblenden; WAV-Export nutzt dasselbe Worklet). Schriften: Latein-Subsets als WOFF in `fonts/` (Neu erzeugen mit `pyftsubset`, Zeichenbereich siehe Commit v63).
- Sample-Kits (v69/v70): `KITS.<id>.samples={dir,voices,fallback}` (studio, s67, hyb, rusty, vintage), Dateien `samples/<dir>/<stimme>.mp3` (Sync-Klick + 12 Slots, Format in `samples/README.md`), Engine `smpLoad`/`smpPlay` (Layer nach Velocity, Round Robin, Variation, Raum je AudioContext), Optionen `smpOpt` (v71: Kit-Auswahl → „Klang“ am gewählten Sample-Kit, eingeklappt; gespeichert mit dem Pattern, ohne Angabe Standard `SMP_OPT_DEF`). `voices` = Rock-Synth als Ersatz beim Laden und für Stimmen ohne Aufnahme. Neue Kits mit `tools/build-samples.py` bauen (einzelne Stimmen: `VOICES=…`). Nicht benutzte Kits frei (`smpFree`).
- Beats-Fenster (v76, Mockup `docs/mockups/neuer-beat-mockup.html` B): Karte „Aktueller Beat“ `#pbCard` (Name `#pbName`, Status `#pbState`, Länge, Speichern = anlegen bzw. überschreiben, Als Kopie, WAV); darüber Leiste `#pbTop` (v88, Mockup `docs/mockups/beats-fenster-mockup.html` G: `#pbNewBtn` · Import · Export), ganzes Fenster scrollt, `#patternList` ohne eigene Höhe. `#pbNewBtn` → Sheet `#newBeatSheet` (`nbMake('keep'|'def')`, Standard = `nbDefault` beim Start, Undo über `hmToast(msg,true,fn)`). Ungespeichert = `pbPrint()` ≠ `pbBase` (geprüft nach pointerup/change), Punkt `.pdirty` im LCD. Ohne id: „Neuer Beat“ = Entwurf, „♫ …“ = Song.
- Spielweisen (v72): `ART={ch:[Zu,Locker,Pedal], rd:[Fläche,Bell]}`, Wert pro Step im sonst leeren `tr.notes[s]` der Drum-Spuren; `triggerTrack(tr,t,vel,art)` → Sample-Stimme `ART[..].v` (ch/hl/hf, rd/rb) bzw. `artSynth`. Leiste `#artRow`, Step-Buchstabe über `data-a`. Ride-Zeile `rd`; Synth-Ride = `rideFromCy`.
- Effekte (v79, Mockup `docs/mockups/effekte-mockup.html` v7): Register `FXDEF` (dist, filter, comp, limit nur Master; `build(ctx)` → `{i,o,u(p)}`), Sends `FX_SEND` (Hall/Delay mit Presets, Standard = bisheriger Klang). Spur: `bus → EQ (eqHp/eqLow/eqMid/eqHigh, nur im Weg wenn nicht neutral) → tr._fxN → post → panner → Master bzw. Drums-Gruppe`; Sends zapfen an `post`. Neu verkabeln: `trFxRebuild(tr)` / `eqApply(tr)`, Master `fxMasterRebuild()`, Delay `fxDelayUpdate()` (Notenwert `FX_NV`, Mono/Ping-Pong), Hall `fxHallUpdate()`, Gruppen (v80) `GRP_DEF` drums/perc, Zustand `grps[k]={vol,muted,fx}`, Spur → `grpIn(tr)` → `FXG.g[k]` (i → Inserts → v → Master), `grpFxRebuild(k)`/`grpUpdate(k)`; Klang-Sheet `openFxRoot('grp',k)`. Alle Bus-Knoten in `FXG`; `buildFxBuses()` baut live und im WAV-Export denselben Aufbau. Zustand: `tr.fx`, `tr.eqOn/eqLc/eqMf` (+ eqLow/Mid/HighGain), `fxHall`, `fxDelay`, `masterFx`, `grps` (alt `grpDrums` wird gelesen) → gespeichert ab `schemaVersion: 8`.
- Mix & FX (Klang-Sheet) = Kanal-Einstellungen im Mixer (`mixFxBody`); Geräte-Ansichten als Stapel `klView` im `#klSheet` (`klPush`, Zurück `#klBack`), Modi `klMode` (klang, kanal, master, grp, send). EQ-Gerät mit Kurve (`eqDraw`, Offline-Kontext für `getFrequencyResponse`). Mixer `buildMixerChannels()` (Gruppe `mxGrpOpen`, Gruppen-Solo `toggleGrpSolo(k)` = Solo aller Spuren der Gruppe, Rückwege Hall/Delay, Master fest), Neuaufbau gebündelt über `mixerRebuild()`. Tests: `tests/test-fx.py`.
- Mixer-Pegel (v93, #50, Mockup `docs/mockups/issue-50.html` B): `readPeak` liest Float-Daten über den ganzen Analyser-Puffer (2048), Skala −48…0 dBFS (`METER_*`), Zonen grün < −12 · gelb −12…−3 · rot ≥ −3 (CSS-Verlauf 75 %/93,75 %), LED-Segmente. CLIP-LED `.mix-clip` + Spitzenwert `.mix-pk` je Kanal, Zustand in `MX_CLIP[key]` (überlebt `mixerRebuild`), Tippen setzt zurück, am Master alle. Master-Meter misst nach den Master-Effekten, vor der Notbremse.
- Master-Kette (v95, #51, Mockup `docs/mockups/issue-51.html` A): `master → Master-Effekte (masterFx) → makeOutStage (js/audio.js) → Ausgang`. Ab Werk `masterFx=mfxDefault()` = Kompressor-Preset „Drumstar“ (= bisher versteckter DynamicsCompressor mit Standardwerten, Knie `kn` 30, Release `re` 250; bitgenau gleich). Alte Speicherstände ohne `mfxV:2` bekommen ihn beim Laden vorn eingefügt (`fxLoadGlobal`), fehlende Kompressor-Felder kommen aus `FXDEF.comp.legacy` (Knie 6, Release 150). Achtung: Web Audio hebt bei jedem DynamicsCompressor automatisch an, „Aufholen“ kommt obendrauf. Notbremse = WaveShaper ohne Verzögerung, bis `BRAKE_KNEE` −1,5 dBFS linear, darüber tanh bis `BRAKE_DB` −0,3 dBFS. Master-Meter misst davor (CLIP = Notbremse greift), Lampe `[data-brake]` im Ausgang der Kette. Absenkung von Kompressor/Limiter (`n.red.reduction`) live in Kette und Gerät (`fxGrLoop`).
- Tempo erkennen (v97, #53, Mockup `docs/mockups/issue-53.html` A): HÖREN-Knopf `#tempoOverlayHear` im Tempo-Fenster. Mikro (`ensureMicStream`, Worklet `mic-recorder` bzw. ScriptProcessor) → `BpmDetector` (Spectral Flux, FFT 1024/Hop 512) → `bpmEstimate` (Autokorrelation + Kamm, 60–200, Phase des letzten Schlags). Live-Schätzung, stoppt nach max. 15 s oder wenn 4 Schätzungen ±1,2 BPM stabil (ab 6 s). Stoppt den Transport. Karte `#tdRes`: ½/×2, Mitklicken (`playMetronomeClick` phasenrichtig), Übernehmen; Aufnahme-Zeile `#tdRecRow` (Anhören, Als Sample → `openSampleEditor({buffer})`). Fenster zu = abbrechen.
- Versionsanzeige (v91): `#appVer` im Fuß der Pattern-Seite zeigt das `?v=` der laufenden index.html; meldet der Service Worker einen neuen Stand im Cache (`update-ready`), steht dort „Update da, antippen“ → neu laden.
- Siehe `CHANGES-v61-v72.md` (neuester Stand, offene Punkte), `DECISIONS.md` (gültige Entscheidungen, Verworfenes, Lektionen, Aufräum-Liste) und `docs/history/` (ältere Changelogs v41–v60). Tests (Playwright, headless) in `tests/`: vor jedem Push `python3 tests/run.py schnell` (ui, editor, fx, walkthrough, sw; ~2½ min; setzt Test-Hook in einer Temp-Kopie von `js/tracks.js`, startet Server, Screenshots in `tests/out/`). Den vollen Satz `python3 tests/run.py` (mit audio, ~8½ min) nur, wenn sich Klang ändern kann: Web-Audio-Knoten, Scheduler/`triggerTrack`, Synthese, Worklet, Samples/Kits (`smp*`, `samples/`, `tools/build-samples.py`), Effekte/EQ/Mixer-Signalweg, WAV-Export, `tests/test-audio.py` oder `tests/hook.js`. Im Zweifel voll. Neue Features bekommen Checks im passenden `test-*.py`.

## Aufgaben & Ideen = GitHub Issues
Einzige Quelle für „was noch“ sind die Issues (Labels: `aufgabe`, `idee`, `bug`, `aufräumen`). Keine Aufgabenlisten in Dateien oder Memory.
- **Session-Start** („weiter machen“): offene Issues lesen (`gh api "repos/Andy-Baker/drumstar/issues?state=open&per_page=100"`; GraphQL/`gh issue` geht hier nicht).
- **Titel**: so formulieren, dass der Nutzer ohne Code-Kenntnis versteht, was es bringt (Bereich + Wirkung, z. B. „Sample-Bibliothek: Samples löschen können“). Interne Namen höchstens im Text.
- **Während der Session**: Neue Idee, Wunsch oder Fehler vom Nutzer sofort als Issue anlegen (knapp, mit Kontext), nicht erst am Ende.
- **Commits**: `fixes #n` bzw. `refs #n` in die Commit-Nachricht.
- **Session-Ende**: Erledigtes geschlossen? Neues angelegt? Rückmeldungen (z. B. Handytest) als Kommentar am Issue.
- Der Nutzer pflegt nichts selbst, kann aber jederzeit in GitHub nachtragen.
