# MRM-44 / Drumstar
Browser-Drum-Machine/Sequencer, Vanilla JS + Web Audio: `index.html` (Markup), `css/app.css`, `js/*.js` (klassische Skripte, gemeinsamer globaler Scope), `sw.js` (Service Worker). Gehostet via GitHub Pages. Sprache: Deutsch, knapp.

## Regeln
- Kein Framework, kein Build. Plain HTML/CSS/JS; was im Repo liegt, läuft so. Mehrere Dateien ja, ES-Module/TypeScript vorerst nein (siehe DECISIONS.md).
- Bei jedem Deploy `CACHE` in `sw.js` erhöhen (aktuell `mrm44-v114`) und alle `?v=` an den js/css-Links in `index.html` auf dieselbe Nummer setzen (`tests/test-sw.py` prüft das).
- Skript-Dateien: Reihenfolge = `<script>`-Liste in `index.html`. Code, der beim Laden läuft (oberste Ebene), darf nur Funktionen aus derselben oder früheren Dateien aufrufen bzw. als Wert übergeben — Hoisting gilt nur innerhalb einer Datei. Start-Aufrufe gehören nach `js/main.js` (wird zuletzt geladen). Neue Datei: in `index.html` eintragen, sonst nichts (der Service Worker liest die Liste von dort).
- UI: erst interaktives Mockup (HTML), dann Umbau. Mockups möglichst wie die echte App darstellen (gleiche Leisten, Abstände, Schriften, Farben, umliegende Elemente der Seite), damit man sich das Ergebnis vorstellen kann; vor dem Verschicken am Handy-Format per Screenshot prüfen (nichts abgeschnitten/verdeckt). Design braucht Platz; dunkles Chassis, blaue Controls, Instrumentfarben (Acid orange, Cosmic lila, Piano gelb, Sampler grün, Drums blau, Perc türkis).
- Versionen über Git-Commits/Tags, nicht über Datei-Suffixe.
- Tests gehören ins Repo (`tests/`), nie nur ins Claude-Projekt. Neue oder geänderte Tests immer mit committen und pushen.

## Architektur-Kurzfassung
- Dateien (`js/`, in Ladereihenfolge): `base` (Icons `UI_IC`, `$id`, Drum-Spuren `DRUM_TRACKS`) · `audio` (Engine, Worklet) · `fx` (Effekte, Busse) · `voices` (Metallic, Mic-Sample, Acid) · `events` (Arrangement, Noten-Events, Cosmic- und Piano-Stimme) · `kits` (Drumsets, Sample-Kits) · `tracks` (`TRACKS`, Fill) · `controls` (Knob, Tempo, Übersicht, Spurleiste; `TR_UI`/`trUi(tr)` = DOM-Elemente je Spur, nicht an der Spur) · `harmony` · `editor` (Step-Grid, Vorschau, Acid-Auto, XY) · `sheets` (Menüs, Sheets, Klang) · `sample-track` (Mikrofon, Würfeln) · `wav-export` (WAV-Export, Sample-Bibliothek) · `sampler` · `mixer` (Sample-Pads, Mixer) · `sample-editor` · `storage` (Pattern-Speicher, Import/Export) · `beats` (Beats, Kit-Menü, Drumset-Editor) · `pianoroll` · `scheduler` (Transport-Engine ohne DOM, Ereignisse `transportOn('start'|'stop'|'step',fn)`; Standard-Pattern, Default-Beats) · `transport-ui` (Play-Taste, Metronom-Schalter, Abspielkopf `visualLoop`, Piano-Roll-Sync, Tab-Leiste) · `tempo-detect` (Tempo erkennen) · `main` (Start).
- Melodische Spuren (`type:'arp'`: arp=Acid, cosmic, piano) nutzen `tr.events=[{s,n,l,v,a,sl}]`; `tr.steps` ist abgeleitet (`evTouch`). Instrument-Register (v109, #24) `INSTR` in `js/events.js`: alles, was Acid/Cosmic/Keys unterscheidet (Name, Gruppe, `poly`, `oct`, `trigger`, `live`, eigene Felder `fields` + `undo`, Klangauswahl `sounds`, Zusatzregler `knobs`, `xy`/`accent`, Harmonie-Standard). `trInst(tr)` = Eintrag (`INSTR[tr.inst||tr.id]`, heute = Spur-ID; #13 setzt `tr.inst`), `isPoly`/`trOct`/`prName` lesen daraus; Speichern/Laden nur über `instSave`/`instLoad` (nur eigene Felder, ungültig → Standard), Klang ab Werk `instTpl(tr)` (= `INSTR[k].tpl`, bleibt auch ohne Original-Spur), Klangauswahl `instSound`/`grpSoundTr`. Weitere Register-Felder (v112): `extra` (keine Spur ab Werk), `tplOf` (Vorlage aus anderem Instrument, `js/tracks.js`), `klang(tr,box,grp)` (eigener Reiter Sound), `sub(tr)` (Zusatz zum Namen → `instSub`), `valid` (Prüfung eigener Felder in `instLoad`). Neue Instrument-Unterschiede gehören ins Register, keine `tr.id==='…'`-Abfragen.
- Freie Melodiespuren (v110, #13 Stufe 1, Mockup `docs/mockups/issue-13.html` C): `js/spuren.js`. Spur = `TRACKS`-Eintrag mit `tr.inst` + eigener ID (`piano2`, …; Original-Spuren id = Instrument, auch löschbar/umbenennbar), Name `tr.label` → `trTitle(tr)`, Kurzname `melShort`. Höchstens `MEL_MAX` 7. `trCreate`/`trAttach`/`trDetach` + danach `melChanged(sel)`; Aktionen `trAddNew` (auch Kopieren mit Clips), `trRename`, `trDelete` (Rückgängig im Toast). Übersichts-Zeile `ovRowMake(tr)`, Gruppen `arrGroupsBuild()` aus `TRACKS` (`ARR_GROUPS_BASE` = Werksaufbau; Gruppen-ID `trGrpId`: Original → acid/cosmic/piano, sonst Spur-ID). Speichern: `mel=[{id,inst,label}]`, Laden `melSync` (fehlt = ACID/COSMIC/KEYS); Spur-Eintrag `trSave`/`trLoadSaved` in `js/storage.js`. Beat-Reiter bleiben je Instrument (`beatMelTrack`: gewählte Spur des Instruments, fehlt → neu anlegen). UI: ⋯ + „Spur hinzufügen“ im Spur-Menü (`trMenuDecorate`), Spurname + „+ Spur“ im Song (`trSongDecorate`), Sheet `#trSheet`.
- Weitere Drum-/Perc-Spuren (v111, #70, Mockup `docs/mockups/issue-70.html` B): auch in `js/spuren.js`. Spur = `DRUM_TRACKS`-Eintrag `drums2`/`perc3` … (`dtExtra(d)`, höchstens `DT_MAX_EXTRA` 3) mit Zeilen `<Stimme>_<n>`; `rowBase(id)` = Stimme ab Werk der Zeile (`trVoice`/`trSwap`/`rowDefVoice`/`kitFits`, Set-Editor, eigene Sets und DRUMS/PERC-Beats rechnen damit; Sets und Beats speichern unter `rowBase`). Anlegen `dtCreate`/`dtAttach` (Zeilen aus `ROW_TPL`), `dtAddNew` (Kopie: Noten, Klang, Tausch, Set, Gruppen-Mix, Clips), `dtDelete` (Rückgängig), `dtRename`; Sheet `dtAddSheet(kind,src)` = Kit- + Zeilen-Chips. Eigener Mixer-Gruppen-Kanal `grpAdd`/`grpRemove` (`grpBusMake`, GRP_KEYS wächst). Hi-Hat-Choke je Drum-Spur (`chokeKey` aus `triggerTrack`, `lastOpenSample`/`lastOpenHatGain` als Objekt). Fill: `roleTracks` nur DRUMS/PERC ab Werk, `fillLayer` kopiert auf weitere Drum-Spuren mit Noten. Beat-Reiter DRUMS/PERC → `beatDrumTarget` (gewählte Spur der Art). Speichern `drt=[{id,kind,name,rows}]`, Laden `dtSync` (zuerst in `applyTrackAndFillData`; fehlt = keine), Kit/Set/Gruppe über `kits`/`drumSet.sets`/`grps` je Spur-ID. DRUMS und PERC ab Werk: nur Kopieren (nicht löschen/umbenennen).
- Sampler (v112, #8, Mockup `docs/mockups/issue-8.html` A): `js/sampler.js`, `INSTR.sampler` (poly, nur über „Spur hinzufügen“, zählt zu `MEL_MAX`). Felder `smp` (Werk-Instrument `str`/`piz`/`kb`/`kba` = `SMP_INSTR`, Standard `str`; Werksample `vox`/`glas`/`bass` = `SMP_WERK`, beim ersten Gebrauch synthetisiert; oder `lib:<id>` aus der Sample-Bibliothek), `smpAtk`/`smpRel`. Werk-Instrumente (v113, #61): echte Aufnahmen (VSCO 2 CE Streicher, Karoryfer Meatbass), mehrere Töne × Lautstärke-Stufen × Round Robin in einer MP3 `samples/instr/<id>-<hash>.mp3`, Karte `js/sampler-werk.js` (erzeugt von `tools/build-instr.py`, nicht von Hand ändern; Format im Kopf des Skripts). Laden `samplerLoadInstr` (Sync-Klick wie Sample-Kits), Slot-Wahl `smpSlot` (nächste Zone, Stufe nach Ziel-Velocity `SMP_LVEL`, Round Robin, Stimmung in Cent je Slot), Pegel `SMP_IGAIN` × `I.g` (Streicher-Dreiklang ≈ KEYS), Schleife für gestrichene Instrumente im Slot eingebacken (`I.loop`). Unbenutzte Instrumente gibt `samplerSync` frei. Puffer-Cache `SMPL` je Sample (`samplerGet`, `samplerSync` lädt alle der Sampler-Spuren; Aufruf nach Laden/Spuränderung und vor dem WAV-Export; `samplerInvalidate` nach Speichern im Sample-Editor). Grundton gehört zum Sample: Bibliothekseintrag `root` (MIDI; fehlt = C4, beim Wählen im Klang-Sheet `smpDetect` = Autokorrelation, kürzeste Periode ≥ 88 % der Spitze). Note → MIDI 33 + `tr.rootNote` + n + 12, Tonhöhe = `playbackRate`. Wiedergabe-Art = `entry.playMode` aus dem Sample-Editor (Einmal = bis zum Ende, Halten = Notenlänge, Schleife = Loop beim Halten). Stimme `samplerVoice` = BufferSource → Gain → `tr.bus`, höchstens `SMP_MAXV` 8, Stopp über `tr._cosVoices`. Klang-Sheet Sound `samplerKlang` (Sample-Chips, Grundton −/+/Erkennen, Hüllkurve), Sample-Editor-Chip „Sampler“ (`openSampleEditor({forSampler:tr})`). Fehlt das Sample: stumm, „Sample fehlt“ im Namen. Die frühere SAMPLE-Spur (`mc`) ist entfernt: `mcMigrate` (in `applyTrackAndFillData`) macht aus alten Ständen mit Noten + zugeordnetem Sample (`localStorage mrm44_sampleTrackId`) eine Sampler-Spur „SAMPLE“ (Noten auf C4, Song-Clips mit), alte Beats aus dem Reiter „Sample“ → `mcBeat` (in `beatAll`). Beat-Reiter „Sampler“ = Gruppe `sampler`.
- Drums/Perc: `tr.steps`.

## Aufgaben & Ideen = GitHub Issues
Einzige Quelle für „was noch“ sind die Issues (Labels: `aufgabe`, `idee`, `bug`, `aufräumen`). Keine Aufgabenlisten in Dateien oder Memory.
- **Session-Start** („weiter machen“): offene Issues lesen (`gh api "repos/Andy-Baker/drumstar/issues?state=open&per_page=100"`; GraphQL/`gh issue` geht hier nicht).
- **Titel**: so formulieren, dass der Nutzer ohne Code-Kenntnis versteht, was es bringt (Bereich + Wirkung, z. B. „Sample-Bibliothek: Samples löschen können“). Interne Namen höchstens im Text.
- **Während der Session**: Neue Idee, Wunsch oder Fehler vom Nutzer sofort als Issue anlegen (knapp, mit Kontext), nicht erst am Ende.
- **Commits**: `fixes #n` bzw. `refs #n` in die Commit-Nachricht.
- **Session-Ende**: Erledigtes geschlossen? Neues angelegt? Rückmeldungen (z. B. Handytest) als Kommentar am Issue.
- Der Nutzer pflegt nichts selbst, kann aber jederzeit in GitHub nachtragen.
